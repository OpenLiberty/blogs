== What are tools for LLMs?

Some LLM models are able to call tools due to their training data, which improves their response and gives them the ability to perform actions. When an AI is given a prompt that it believes it cannot do, it tries to search for a tool that can best perform the task. This ability greatly enhances LLMs as they can start doing tasks for you or use online APIs and databases to access the web and better their response.

Many models such as Llama, GPT-4.1, and Devstral support the ability to call and run tools. Some can be found on AI providers such as GitHub, Mistral AI, and Ollama.
=======
== Understanding LLM Tool Calling

Tool calling is a capability where LLMs can identify when to invoke external functions and with what parameters. In technical terms, when an LLM determines that a user query requires information or actions beyond its training data, it generates a structured function call with appropriate arguments rather than attempting to hallucinate an answer.

For example, when asked about current Stack Overflow issues with a specific library, instead of providing potentially outdated information from its training data, the LLM can:
1. Recognize the need for current information
2. Call an appropriate search function with the correct query parameters
3. Process the returned data to formulate a response

Tool-enabled models like Llama 3.1, GPT-4o, Claude 3 Opus, and Mistral Large support this capability through standardized JSON function calling interfaces. In this tutorial, we'll use models available through GitHub Copilot, Ollama, and Mistral AI platforms.

== How to take advantage of using AI with tools in Java applications?

Creating tools by hand for models can be hard. The open source project LangChain has abstractions and tools to allow for a common interface to use tools for several models.

You can use community projects like https://github.com/langchain4j/langchain4j[LangChain4j] to help speed development with AI and tools. LangChain4j APIs can help integrate LLMs into your Java application for different AI platforms by using one interface. They allow for simple development of integrating tools with several models and providers.
=======
== LangChain4j: A Java Framework for LLM Tool Integration

Implementing tool calling directly with LLM APIs requires handling complex JSON schemas, managing context windows, and dealing with provider-specific implementations. LangChain4j solves these challenges by providing:

1. A unified Java interface for multiple LLM providers
2. Simple annotations for converting Java methods into LLM tools
3. Automatic handling of parameter serialization and response parsing
4. Memory management for maintaining conversation context
5. Error handling for hallucinated tool calls

The https://github.com/langchain4j/langchain4j[LangChain4j] library lets you focus on your business logic rather than LLM integration details. With simple annotations like `@Tool` and `@P`, you can expose any Java method to an LLM, making it particularly valuable for Jakarta EE applications where you might want to integrate AI capabilities with existing enterprise services.

== How does the application work?

The application demonstrates how to use the https://docs.langchain4j.dev/tutorials/tools[LangChain4j Tools], https://openliberty.io/docs/ref/feature/cdi-4.0.html[Jakarta Contexts and Dependency Injection], https://openliberty.io/docs/latest/reference/feature/websocket-2.1.html[Jakarta WebSocket], and https://openliberty.io/docs/ref/feature/mpConfig-3.0.html[MicroProfile Config] features.

Each AI model can only provide static data, which may be outdated based on what it was trained on. You can use the AI tools to enhance the interaction with the AI model by calling other third-party APIs, querying more data from database, or performing complex tasks.

The AI model in this sample application is given tools to search from the https://stackoverflow.com[Stack Overflow website] which developers use to post their questions and answers. This allows users to efficiently search for relevant information from Stack Overflow with the help of AI without leaving the chat application. Those tools give the ability to return additional information from the Stack Overflow beyond the AI model. Thus, if the AI model is prompted with a question that it cannot solve, it uses a matched tool to search on the Stack Overflow. The tool searches questions by using the https://api.stackexchange.com/docs/excerpt-search[StackExchange excerpt-search API] that find the first question similar to what the user is asking. If the question has at least one answer, the tool calls another API to get the top answer and return the question ID, question, and top answer back to the AI model. The AI model parses the data, constructs a reply, and sends the reply to the user.
=======
== Technical Implementation Details

The application architecture consists of four main components that work together to provide an AI assistant with tool-calling capabilities:

1. **Tool Implementation** (`StackOverflowTools.java`) - Java methods annotated to be callable by the LLM
2. **AI Service** (`ChatAgent.java`) - Configures the LLM and exposes it through a Java interface
3. **WebSocket Endpoint** (`ChatService.java`) - Handles real-time communication with clients
4. **Frontend** (`toolChat.js` and `toolChat.html`) - Provides the user interface

When a user sends a message through the WebSocket, the following sequence occurs:

1. The message is received by the `ChatService` endpoint
2. The message is forwarded to the `ChatAgent`, which sends it to the configured LLM
3. The LLM analyzes the message and determines if it needs to call a tool
4. If needed, the LLM generates a tool call with appropriate parameters
5. LangChain4j executes the corresponding Java method with those parameters
6. The tool result is returned to the LLM, which incorporates it into its response
7. The final response is sent back to the client through the WebSocket

This implementation specifically uses the Stack Overflow API to enhance the LLM's capabilities. When the user asks a technical question that might benefit from current Stack Overflow data, the LLM calls the appropriate search method, which:

1. Queries the Stack Exchange API to find relevant questions
2. Retrieves the top answer for each question
3. Returns the formatted results to the LLM
4. The LLM then synthesizes this information into a coherent response

The `ChatAgent` class serves as the bridge between your application and the LLM. It handles:
1. LLM provider configuration
2. Tool registration
3. Conversation memory management
4. Error handling for hallucinated tool calls

public Assistant getAssistant() {

    assistant = AiServices.builder(Assistant.class)
        .chatModel(model)
        .tools(stackOverflowTools)
        .hallucinatedToolNameStrategy(toolExecutionRequest -> 
            ToolExecutionResultMessage.from(toolExecutionRequest, 
                "Error: there is no tool with the following parameters called " + 
                toolExecutionRequest.name()))

        .build();

}

Key configuration elements include:

1. **Tool Registration** - The `tools()` method registers your tool classes with the LLM
   
2. **Hallucination Handling** - The `hallucinatedToolNameStrategy` provides graceful error handling when the LLM attempts to call a non-existent tool (a common issue with LLMs)
   
3. **Memory Management** - The `chatMemoryProvider` configures conversation history retention, which is essential for maintaining context across multiple messages

=== WebSocket Integration

The application uses Jakarta WebSocket to provide real-time communication between the client and the AI service. This approach offers several advantages over traditional REST endpoints:

1. **Real-time interaction** - Immediate responses without polling
2. **Persistent connection** - Reduced overhead for multiple messages
3. **Session management** - Easy tracking of conversation state

The server-side implementation uses standard Jakarta WebSocket annotations:

[source,java]
----
@ServerEndpoint(value = "/chat", encoders = {JsonEncoder.class})
public class ChatService {
    @Inject
    ChatAgent agent;
    
    @OnMessage
    public void onMessage(String message, Session session) {
        String sessionId = session.getId();
        String answer = "Sorry, I couldn't process your request.";
        
        try {
            answer = agent.chat(sessionId, message);
        } catch (Exception e) {
            logger.log(Level.SEVERE, "Error processing message", e);
            answer = "An error occurred: " + e.getMessage();
        }

        try {
            session.getBasicRemote().sendObject(answer);
        } catch (Exception e) {
            logger.log(Level.SEVERE, "Error sending response", e);
        }
    }
    
    // Other WebSocket lifecycle methods...
}
----

Key implementation details:

1. **Session Management** - Each WebSocket connection gets a unique `sessionId` that's passed to the AI service to maintain conversation context
   
2. **Error Handling** - Robust error handling ensures users receive appropriate feedback even when issues occur
   
3. **Asynchronous Processing** - The WebSocket architecture naturally supports the potentially long processing times of LLM requests

== Conclusion: Building AI-Powered Java Applications with Tool Calling

In this tutorial, we've explored how to implement LLM tool calling capabilities in Jakarta EE applications using LangChain4j. By following the implementation patterns demonstrated here, you can extend your own applications with AI capabilities that go beyond simple text generation.

Key technical concepts we've covered include:

1. **Tool Definition** - Using `@Tool` and `@P` annotations to expose Java methods to LLMs

3. **Error Handling** - Implementing strategies for handling hallucinated tool calls
4. **WebSocket Integration** - Creating real-time communication channels between users and AI services
5. **Memory Management** - Maintaining conversation context across multiple interactions

The approach demonstrated here offers several advantages for Java developers:

- **Separation of Concerns** - Your business logic remains in standard Java methods, cleanly separated from AI integration
