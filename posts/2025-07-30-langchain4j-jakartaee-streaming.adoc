The introduction of LLMs opens the possibility for users to interact in natural language with your application. As your application grows however, your users may need to wait longer for a response from the LLM. By streaming the response to the user as the LLM generates it, you improve user experience by reducing delays and increasing responsiveness.

== Try out the streaming chat sample application

You can check out our sample application integrating LangChain4j's streaming chat with a Jakarta EE application by cloning the https://github.com/OpenLiberty/sample-langchain4j.git[sample-langchain4j] repo and going to the streaming-chat project using the commands below:

[source,console]
----
$ git clone https://github.com/OpenLiberty/sample-langchain4j.git
$ cd sample-langchain4j/streaming-chat
----

Set the JAVA_HOME environment variable to your Java 21 or newer installation path. You can install the https://developer.ibm.com/languages/java/semeru-runtimes/downloads[IBM Semeru Runtime] as your Java runtime. Follow the set up instructions for your provider (e.g. GitHub Models, Ollama, Mistral AI, Hugging Face). Check the https://github.com/OpenLiberty/sample-langchain4j/blob/main/streaming-chat/README.md[README] for detailed setup instructions.

Start the sample application by running `./mvnw liberty:dev` if you are on MacOS or Linux, and `mvnw.cmd liberty:dev` if you are on Windows. Once the server has started, go to http://localhost:9080, send a message, and check out how the response is streamed token by token.

== How do I set up streaming chat?

To start, build a streaming chat model from a provider of your choice (e.g, GitHub Models, Ollama, Mistral AI, Hugging Face) and set a 200 token limit on the response. The code below shows how to build an Ollama streaming chat model using the Llama3.2 model.

[source,java]
----
StreamingChatModel streamingModel = OllamaStreamingChatModel.builder()
	.baseUrl("http://localhost:11434")
	.modelName("llama3.2")
	.numPredict(200)
	.build();
----

Declare an assistant interface with a chat method that LangChain4j will implement. To support multiple user conversations at the same time, it should extend ChatMemoryAccess which provides a method to delete conversation history such as when a user leaves. We can also specify a system message to influence the assistant's responses, such as being knowledgeable about the OpenLiberty application server.

[source,java]
----
interface StreamingAssistant extends ChatMemoryAccess {
	@SystemMessage("You are a helpful chat bot knowledgeable about the OpenLiberty application server.")
	TokenStream streamingChat(@MemoryId String sessionId, @UserMessage String userMessage);
}
----

Build an AI service implementing the interface using the streaming chat model from earlier, with the 10 most recent messages of each conversation preserved.

[source,java]
----
StreamingAssistant assistant = AiServices.builder(StreamingAssistant.class)
	.streamingChatModel(streamingModel)
	.chatMemoryProvider(sessionId -> MessageWindowChatMemory.withMaxMessages(10))
	.build();
----

=== Set up the WebSocket endpoint

Use JakartaEE's WebSocket annotations to declare a server endpoint that the front end will connect to.

[source,java]
----
@ServerEndpoint("/streamingchat")
public class StreamingChatService {
	...
}
----

For each user message, use the assistant created earlier to generate a response. As the model generates the response, LangChain4j will call the callback given to `.onPartialResponse(...)` with each token, which gets sent through the WebSocket using `.sendText(token)`. If the response was cut short because of the token limit, end the response with an ellipsis (`...`). The end of the response is signalled by sending an empty string.

[source,java]
----
@OnMessage
public void onMessage(Session session, String message) throws Exception {
	CompletableFuture<ChatResponse> response = new CompletableFuture<>();
	assistant.streamingChat(session.getId(), message)
		.onPartialResponse(token -> {
			try {
				session.getBasicRemote().sendText(token);
				Thread.sleep(100);
			} catch (Exception error) {
				throw new RuntimeException(error);
			}
		})
		.onCompleteResponse(response::complete)
		.onError(response::completeExceptionally)
		.start();
	if (response.get().finishReason() == LENGTH)
		session.getBasicRemote().sendText(" ...");
	session.getBasicRemote().sendText("");
}
----

For now, when errors occur, send the error message back to the user.

[source,java]
----
@OnError
public void onError(Session session, Throwable error) throws Exception {
	session.getBasicRemote().sendText("My failure reason is:\n\n" + error.getMessage());
	session.getBasicRemote().sendText("");
}
----

Make sure to remove a user's chat history using `.evictChatMemory(...)` when they disconnect, such as after closing the tab.

[source,java]
----
@OnClose
public void onClose(Session session) {
	assistant.evictChatMemory(session.getId());
}
----

=== Set up a simple frontend

For the frontend, create a simple UI which can show user messages and AI responses.

[source,html]
----
<!DOCTYPE html>
<html>
	<head>
		<title>AI Chat Room</title>
		<style>...</style>
	</head>
	<body>
		<h1>Chat Room - streaming chat example</h1>
		<div id="messages"></div>
		<form id="form" action="javascript:void 0;">
			<label for="input">My message:</label>
			<input id="input" type="text" required />
			<button id="button" type="submit">Send</button>
		</form>
		<script>...</script>
	</body>
</html>
----

We can style the UI to show user messages on the right and AI responses on the left.

[source,css]
----
body {
	margin: 0 auto;
	padding: 0 1rem;
	max-width: 80ch;
	word-break: break-word;
	* { max-width: 100%; }
}
.mine {
	max-width: 60ch;
	margin-left: auto;
	text-align: right;
	&::before { content: "Me: "; }
}
.ai {
	max-width: 60ch;
	white-space: pre-wrap;
	&::before { content: "AI: "; }
	&:empty::after { content: "thinking..."; }
}
form {
	text-align: right;
}
----

On the frontend, create a WebSocket connection to the server endpoint.

[source,javascript]
----
var messages = document.getElementById('messages');
var form = document.getElementById('form');
var input = document.getElementById('input');
var button = document.getElementById('button');

// Connect to websocket
var webSocket = new WebSocket(
	(window.location.protocol == 'https:' ? 'wss:' : 'ws:')
	+ '//' + window.location.host + '/streamingchat'
);
----

When the user presses Enter, send the message to the server through the WebSocket created earlier and disable the button.

[source,javascript]
----
form.addEventListener('submit', function () {
	var myMessage = document.createElement('p');
	myMessage.className = 'mine';
	myMessage.textContent = input.value;
	var aiMessage = document.createElement('p');
	aiMessage.className = 'ai';
	messages.append(myMessage, aiMessage);

	webSocket.send(input.value);
	form.reset();
	button.disabled = true;
});
----

Add each new token to the AI's last message element until an empty string is received. Re-enable the send button as the empty string ends the response.

[source,javascript]
----
webSocket.addEventListener('message', function (event) {
	if (event.data != '')
		messages.lastChild.textContent += event.data;
	else
		button.disabled = false;
});
----

Display an error message if the WebSocket was closed for any reason.

[source,javascript]
----
webSocket.addEventListener('close', function (event) {
	var errorMessage = document.createElement('p');
	errorMessage.textContent = 'Error: Connection closed unexpectedly.';
	messages.append(errorMessage);
	button.disabled = true;
});
----
