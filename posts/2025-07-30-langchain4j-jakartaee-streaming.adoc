= LangChain4j streaming chat works with Jakarta WebSocket
George Zhang <https://github.com/GeeTransit>
:imagesdir: /
:url-prefix:
:url-about: /

The introduction of large language models (LLMs) opens the possibility for users to interact in natural language with your application. However, as your application grows, your users need to wait longer for a response from the LLM. You can improve the user experience by streaming the response to the user as the LLM generates it, in doing so reducing delays and increasing responsiveness.

In this post, you can explore how to enable two-way communication between client and server endpoints and how to stream tokens from your LLM to your application client UI with Jakarta WebSocket.

== Try out the streaming chat sample application

You can check out a sample application that integrates LangChain4j's streaming chat with a Jakarta EE application. Clone the https://github.com/OpenLiberty/sample-langchain4j.git[sample-langchain4j] repository and go into the streaming-chat project by using the following commands:

[source,console]
----
$ git clone https://github.com/OpenLiberty/sample-langchain4j.git
$ cd sample-langchain4j/streaming-chat
----

Install Java 21 or newer if you haven’t already. You can use the https://developer.ibm.com/languages/java/semeru-runtimes/downloads[IBM Semeru Runtime] as your chosen Java runtime. Set the `JAVA_HOME` environment variable to your Java installation path.

The application supports the GitHub, Ollama, and Mistral AI providers. You can choose either of them and set up by following the *Prerequisites* and *Environment Set Up* instructions in the https://github.com/OpenLiberty/sample-langchain4j/blob/main/streaming-chat/README.md[streaming-chat readme file].

Start the sample application by running `./mvnw liberty:dev` if you are on MacOS or Linux, and `mvnw.cmd liberty:dev` if you are on Windows. When the server starts, go to the http://localhost:9080 URL, send a question (for example "What are large language models?"), and check out how the response is streamed token by token.

== How to set up streaming chat?

To start, build a streaming chat model from a provider of your choice and set a 200 token limit on the response. The following code shows how to build an Ollama streaming chat model that uses the Llama3.2 model.

See the https://github.com/OpenLiberty/sample-langchain4j/blob/7112a4f14bc7b63bd97f8f123f6ba3c16fdebba9/streaming-chat/src/main/java/io/openliberty/sample/langchain4j/util/ModelBuilder.java#L93-L99[ModelBuilder.java file] to learn more.

[source,java]
----
StreamingChatModel streamingModel = OllamaStreamingChatModel.builder()
	.baseUrl("http://localhost:11434")
	.modelName("llama3.2")
	.numPredict(200)
	.build();
----

Declare an assistant interface with a chat method that LangChain4j can implement. To support multiple user conversations at the same time, extend the ChatMemoryAccess interface that provides a method to delete conversation history such as when a user exits. You can also specify a system message to influence the assistant's responses, such as being knowledgeable about the OpenLiberty application server.

See the https://github.com/OpenLiberty/sample-langchain4j/blob/7112a4f14bc7b63bd97f8f123f6ba3c16fdebba9/streaming-chat/src/main/java/io/openliberty/sample/langchain4j/StreamingChatAgent.java#L43-L46[StreamingChatAgent.java file] to learn more.

[source,java]
----
interface StreamingAssistant extends ChatMemoryAccess {
	@SystemMessage("You are a helpful chat bot knowledgeable about the Open Liberty application server runtime.")
	TokenStream streamingChat(@MemoryId String sessionId, @UserMessage String userMessage);
}
----

Build an AI service that implements the interface and uses the streaming chat model from earlier, with the 10 most recent messages of each conversation preserved.

See the https://github.com/OpenLiberty/sample-langchain4j/blob/7112a4f14bc7b63bd97f8f123f6ba3c16fdebba9/streaming-chat/src/main/java/io/openliberty/sample/langchain4j/StreamingChatAgent.java#L53-L57[StreamingChatAgent.java file] to learn more.

[source,java]
----
StreamingAssistant assistant = AiServices.builder(StreamingAssistant.class)
	.streamingChatModel(streamingModel)
	.chatMemoryProvider(sessionId -> MessageWindowChatMemory.withMaxMessages(10))
	.build();
----

=== Declare the WebSocket endpoint

Use JakartaEE's WebSocket annotations to declare a server endpoint that the front end can connect to.

See the https://github.com/OpenLiberty/sample-langchain4j/blob/7112a4f14bc7b63bd97f8f123f6ba3c16fdebba9/streaming-chat/src/main/java/io/openliberty/sample/langchain4j/StreamingChatService.java#L33[StreamingChatService.java file] to learn more.

[source,java]
----
@ServerEndpoint("/streamingchat")
public class StreamingChatService {
	...
}
----

For each user message, use the assistant to generate a response. As the model generates the response, LangChain4j calls the callback that is given to `.onPartialResponse(...)` with each token, which gets sent through the WebSocket by `.sendText(token)`. If the response was cut short because of the token limit, end the response with an ellipsis (`...`). The end of the response is signaled by sending an empty string.

See the https://github.com/OpenLiberty/sample-langchain4j/blob/7112a4f14bc7b63bd97f8f123f6ba3c16fdebba9/streaming-chat/src/main/java/io/openliberty/sample/langchain4j/StreamingChatService.java#L49-L77[StreamingChatService.java file] to learn more.

[source,java]
----
@OnMessage
public void onMessage(Session session, String message) throws Exception {
	CompletableFuture<ChatResponse> response = new CompletableFuture<>();
	assistant.streamingChat(session.getId(), message)
		.onPartialResponse(token -> {
			try {
				session.getBasicRemote().sendText(token);
				Thread.sleep(100);
			} catch (Exception error) {
				throw new RuntimeException(error);
			}
		})
		.onCompleteResponse(response::complete)
		.onError(response::completeExceptionally)
		.start();
	if (response.get().finishReason() == LENGTH)
		session.getBasicRemote().sendText(" ...");
	session.getBasicRemote().sendText("");
}
----

For now, when errors occur, send the error message back to the user.

See the https://github.com/OpenLiberty/sample-langchain4j/blob/7112a4f14bc7b63bd97f8f123f6ba3c16fdebba9/streaming-chat/src/main/java/io/openliberty/sample/langchain4j/StreamingChatService.java#L85-L90[StreamingChatService.java file] to learn more.

[source,java]
----
@OnError
public void onError(Session session, Throwable error) throws Exception {
	session.getBasicRemote().sendText("My failure reason is:\n\n" + error.getMessage());
	session.getBasicRemote().sendText("");
}
----

The chat history of the user is removed by calling `.evictChatMemory(...)` when they disconnect.

See the https://github.com/OpenLiberty/sample-langchain4j/blob/7112a4f14bc7b63bd97f8f123f6ba3c16fdebba9/streaming-chat/src/main/java/io/openliberty/sample/langchain4j/StreamingChatService.java#L79-L83[StreamingChatService.java file] to learn more.

[source,java]
----
@OnClose
public void onClose(Session session) {
	assistant.evictChatMemory(session.getId());
}
----

=== Connect from the front end

On the front end, create a WebSocket connection to the server endpoint.

See the https://github.com/OpenLiberty/sample-langchain4j/blob/7112a4f14bc7b63bd97f8f123f6ba3c16fdebba9/streaming-chat/src/main/webapp/streamingChat.js#L24[streamingChat.js file] to learn more.

[source,javascript]
----
// Connect to websocket
var webSocket = new WebSocket('/streamingchat');
----

When the user presses Enter, send the message to the server through the WebSocket created earlier and disable sending messages.

See the https://github.com/OpenLiberty/sample-langchain4j/blob/7112a4f14bc7b63bd97f8f123f6ba3c16fdebba9/streaming-chat/src/main/webapp/streamingChat.js#L5-L12[streamingChat.js file] to learn more.

[source,javascript]
----
function sendMessage() {
	var message = input.value;
	appendMessage('my-msg', message, new Date().toLocaleTimeString());
	appendMessage('thinking-msg', 'thinking...');
	webSocket.send(message);
	input.value = '';
	sendButton.disabled = true;
};
----

Add each new token to the AI's last message element until an empty string is received, in which case re-enable sending messages as the empty string ends the response.

See the https://github.com/OpenLiberty/sample-langchain4j/blob/7112a4f14bc7b63bd97f8f123f6ba3c16fdebba9/streaming-chat/src/main/webapp/streamingChat.js#L30-L40[streamingChat.js file] to learn more.

[source,javascript]
----
webSocket.onmessage = function (event) {
	if (event.data != '') {  // stream ends with empty string
		if (messages.lastChild.querySelector('.thinking-msg')) {  // if this is the first token
			messages.removeChild(messages.lastChild);
			appendMessage('agent-msg', '', new Date().toLocaleTimeString());
		}
                messages.lastChild.querySelector('.agent-msg').textContent += event.data;
	} else {
		sendButton.disabled = false;
	}
};
----

Display an error message if the WebSocket was closed for any reason.

See the https://github.com/OpenLiberty/sample-langchain4j/blob/7112a4f14bc7b63bd97f8f123f6ba3c16fdebba9/streaming-chat/src/main/webapp/streamingChat.js#L46-L50[streamingChat.js file] to learn more.

[source,javascript]
----
webSocket.onclose = function (event) {
	...
	appendMessage('agent-msg', 'The connection to the streaming chat service was closed.');
	sendButton.disabled = true;
};
----
