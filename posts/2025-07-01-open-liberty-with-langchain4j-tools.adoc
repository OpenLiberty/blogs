With the recent advances in Artificial Intelligence (AI), there are several new cutting-edge features that can transform how people use large language models (LLM). One new feature is giving LLM's the ability to call tools, giving them the power to use new features to help automate or enhance their responses.

In this post, we'll explore how to give AI tools in Java applications using LangChain4j. We'll also get started using them in an example Jakarta EE/MicroProfile app.

[#what_Are_LLMs_with_tools]
== What are tools for LLMs?

For certain LLM models, they have the capability to call tools set in their programs to improve their response or perform actions. This greatly enhances the capability of LLMs since they can start doing tasks for you automatically or search for current news on the web.

Many models support calling tools such as Ollama, OpenAI, MistralAI and many more models.

[#Java_LLMs_Tools]
== How can we take advantage of using AI with tools in Java applications?

Creating tools by hand for models can be hard. The open source project LangChain has abstractions and tools to allow for a common interface to use tools for several models.

We can use community projects like https://github.com/langchain4j/langchain4j[LangChain4j] to help speed development with AI and tools. LangChain4j APIs can help integrate LLMs into your Java application for different AI platforms using a similar interface to allow for easy development of integrating tools with several models and providers.

image::/img/blog/langchain4j.png[langchain4j GitHub README image,width=70%,align="center"]

[#using_Langchain4j]
== How to use LangChain4j in a Jakarta EE and MicroProfile application

Langchain4j has a useful open source https://github.com/langchain4j/langchain4j-examples[langchain4j-examples] GitHub repository where it stores example applications. We built one ourselves called `jakartaee-microprofile-example`, which can be found in this https://github.com/langchain4j/langchain4j-examples/tree/main/jakartaee-microprofile-example[langchain4j-examples] GitHub repository. However, we created another repository to showcase the many other features of AI such as streaming chat, RAG and tools which could be found here https://github.com/OpenLiberty/sample-langchain4j[sample-langchain4j] but we will focus more on tools, https://github.com/OpenLiberty/sample-langchain4j/tree/main/tools[sample-langchain4j].

[#pre-reqs]
=== Prerequisites
Before you clone the application to your machine, install JDK 21, and ensure that your `JAVA_HOME` environment variable is set.  You can use the https://developer.ibm.com/languages/java/semeru-runtimes/downloads[IBM Semeru Runtime] as your chosen Java runtime. This runtime offers performance benefits from deep technology investment in projects such as Eclipse OpenJ9 and is available across a wide variety of hardware and software platforms. To find out more about IBM Semeru Runtime, see https://openliberty.io/blog/2022/08/19/open-liberty-semeru-performance.html[Open Liberty and Semeru Runtimes, cloud-native performance that matters].

The application uses several providers, you may use one of the following:

    -   Github
        -   Sign up and sign in to https://github.com.
        -   Go to your [Settings](https://github.com/settings/profile)/[Developer Settings](https://github.com/settings/developers)/[Persional access tokens](https://github.com/settings/personal-access-tokens).
        -   Generate a new token
    -   Ollama
        -   Download and install [Ollama](https://ollama.com/download)
            -   see the [README.md](https://github.com/ollama/ollama/blob/main/README.md#ollama)
        -   Pull the following model
            -   `ollama pull llama3.2`
    -   Mistral AI
        -   Sign up and log in to https://console.mistral.ai/home.
        -   Go to [Your API keys](https://console.mistral.ai/api-keys).
        -   Create a new key.
    -   Hugging Face
        -   Sign up and log in to https://huggingface.co.
        -   Go to [Access Tokens](https://huggingface.co/settings/tokens).
        -   Create a new access token with `read` role.

To access the repository remotely, install https://git-scm.com/book/en/v2/Getting-Started-Installing-Git[Git] if you haven't already. You can clone the `sample-langchain4j` GitHub repository to your local machine by running the following command:

[source]
----
git clone https://github.com/OpenLiberty/sample-langchain4j.git
----

[#env_setup]
=== Environment setup

To run the application, navigate to the `sample-langchain4j/tools` directory:

[source]
----
cd sample-langchain4j/tools
----

Set the following environment variables, dependent on your chosen provider:

[source]
----
export JAVA_HOME=<your Java 21 home path>
----

Set the `GITHUB_API_KEY` environment variable if using Github.

---
unset HUGGING_FACE_API_KEY
unset OLLAMA_BASE_URL
unset MISTRAL_AI_API_KEY
export GITHUB_API_KEY=<your Github API token>
---

Set the `OLLAMA_BASE_URL` environment variable if using Ollama. Use your Ollama URL if not using the default.

---
unset HUGGING_FACE_API_KEY
unset GITHUB_API_KEY
unset MISTRAL_AI_API_KEY
export OLLAMA_BASE_URL=http://localhost:11434
---

Set the `MISTRAL_AI_API_KEY` environment variable if using Mistral AI.

---
unset HUGGING_FACE_API_KEY
unset GITHUB_API_KEY
unset OLLAMA_BASE_URL
export MISTRAL_AI_API_KEY=<your Mistral AI API key>
---

Set the `HUGGING_FACE_API_KEY` environment variable if using Hugging Face.

---
unset GITHUB_API_KEY
unset OLLAMA_BASE_URL
unset MISTRAL_AI_API_KEY
export HUGGING_FACE_API_KEY=<your Hugging Face read token>
---

[#create_tool]
=== Creating the tools

We create functions that the AI is allowed to call by annotating it with `@Tool` and explaining the premise of the function. If there are any parameters, we annotate with `@P` to explain what it represents. This helps the AI distinguish when to call the tool and what to put as parameters. If the function returns something, the AI can use it to customize its response back to the user.

See the {example-location} file.
[source, java, role="no_copy"]
----
public class StackOverflowTools {
    ...
   @Tool("Multiple JakartaEE Questions on stackoverflow")
    public String searchJakartaEEQuestions() {
        ...
    }

    @Tool("Multiple MicroProfile Questions on stackoverflow")
    public String searchMicroProfileQuestions() {
        ...
    }

    @Tool("Multiple LangChain4j Questions on stackoverflow")
    public String searchLangChain4jQuestions() {
        ...
    }

    @Tool("Search for questions and answers on stackoverflow")
    public String searchStackOverflow(@P("Question you are searching") String question) {
        ...
    }
    ...
}
----

[#create_service]
=== Creating the LangChain4j AI service

The application creates the model with extra parameters to include what tools the AI can call and what it should when it hallucinates non-existent tools.

See the {example-location}/src/main/java/dev/langchain4j/example/chat/ChatAgent.java[src/main/java/dev/langchain4j/example/chat/ChatAgent.java] file.
[source, java, role="no_copy"]
----
    public Assistant getAssistant() {
        ...
            ChatModel model = modelBuilder.getChatModel();
            assistant = AiServices.builder(Assistant.class)
                .chatModel(model)
                .tools(stackOverflowTools)
                .hallucinatedToolNameStrategy(toolExecutionRequest -> ToolExecutionResultMessage.from(
                    toolExecutionRequest, "Error: there is no tool with the following parameters called" + toolExecutionRequest.name()))
                .chatMemoryProvider(
                    sessionId -> MessageWindowChatMemory.withMaxMessages(MAX_MESSAGES))
                .build();
       ...
    }
----

Through the customized `Assistant` interface, the application can send messages to the LLM by its `chat()` method customized with the system message telling the AI what its role and tasks are.

----
    interface Assistant {
        @SystemMessage("You are a coding helper, people will go to you for questions around coding. " +
            "You have ONLY four tools. " +
            "ONLY use the tools if NECESSARY. " +
            "ALWAYS follow the tool call parameters exactly and make sure to provide ALL necessary parameters. " +
            "Do NOT add more parameters than needed" + 
            "NEVER give the user unnecessary information. " + 
            "NEVER lie or make information up, if you are unsure say so.")
        String chat(@MemoryId String sessionId, @UserMessage String userMessage);
    }
----

[#communicate]
=== Communicating between the client and LLM

The application provides the interactive UI client for users to communicate with the LLM. Jakarta WebSocket enables two-way communication between the client and the `ChatService` service. Each client makes an HTTP connection to the service and send out the messages by the `send()` method.

See the {example-location}/src/main/webapp/chatroom.js[src/main/webapp/chatroom.js] file.
[source, java, role="no_copy"]
----

    const webSocket = new WebSocket(uri);
    ...
    function sendMessage() {
        ...
        var myMessage = document.getElementById('myMessage').value;
        ...
        webSocket.send(myMessage);
        ...
    }
----

The service receives the user messages through the WebSocket `onMessage()` method, forwards them to the LLM by calling the `ChatAgent.chat()` method, and then broadcasts the LLM answers back to the client session through the `sendObect()` method.

See the {example-location}/src/main/java/dev/langchain4j/example/chat/ChatService.java[src/main/java/dev/langchain4j/example/chat/ChatService.java] file.
[source, java, role="no_copy"]
----

    @OnMessage
    public void onMessage(String message, Session session) {
        ...
        try {
            ...
            answer = agent.chat(sessionId, message);
        } catch (Exception e) {
            ...
        }

        try {
            session.getBasicRemote().sendObject(answer);
        } catch (Exception e) {
            e.printStackTrace();
        }

    }
----


If you are interested in other ways to use the LangChain4j APIs, you can study the REST APIs that are provided by the {example-location}/src/main/java/dev/langchain4j/example/rest/ModelResource.java[src/main/java/dev/langchain4j/example/rest/ModelResource.java] file.
