With the recent advances in Artificial Intelligence (AI), there are several new cutting-edge features that can transform how people use large language models (LLM). One new feature is giving LLM's the ability to call tools, giving them the power to use new features to help automate or enhance their responses.

In this post, we'll explore how to give AI tools in Java applications using LangChain4j. We'll also get started using them in an example Jakarta EE/MicroProfile app.

[#what_Are_LLMs_with_tools]
== What are tools for LLMs?

For certain LLM models, they have the capability to call tools set in their programs to improve their response or perform actions. This greatly enhances the capability of LLMs as they can start doing tasks for you automatically or use online APIs to access the web.

Many models such as ollama, GPT-4.1, devstral support the ability to call tools. Some can be found on AI providers such as Ollama, GitHub, and MistralAI.

[#Java_LLMs_Tools]
== How can we take advantage of using AI with tools in Java applications?

Creating tools by hand for models can be hard. The open source project LangChain has abstractions and tools to allow for a common interface to use tools for several models.

We can use community projects like https://github.com/langchain4j/langchain4j[LangChain4j] to help speed development with AI and tools. LangChain4j APIs can help integrate LLMs into your Java application for different AI platforms using a similar interface to allow for easy development of integrating tools with several models and providers.

image::/img/blog/langchain4j.png[langchain4j GitHub README image,width=70%,align="center"]

[#using_Langchain4j]
== How to use LangChain4j in a Jakarta EE and MicroProfile application

Langchain4j has a useful open source https://github.com/langchain4j/langchain4j-examples[langchain4j-examples] GitHub repository where it stores example applications. We created another repository to showcase the many other features of AI such as streaming chat, RAG and tools which could be found here https://github.com/OpenLiberty/sample-langchain4j[sample-langchain4j]. We will focus more on tools, https://github.com/OpenLiberty/sample-langchain4j/tree/main/tools[sample-langchain4j/tools].

[#pre-reqs]
=== Prerequisites
Before you clone the application to your machine, install JDK 21, and ensure that your `JAVA_HOME` environment variable is set.  You can use the https://developer.ibm.com/languages/java/semeru-runtimes/downloads[IBM Semeru Runtime] as your chosen Java runtime. This runtime offers performance benefits from deep technology investment in projects such as Eclipse OpenJ9 and is available across a wide variety of hardware and software platforms. To find out more about IBM Semeru Runtime, see https://openliberty.io/blog/2022/08/19/open-liberty-semeru-performance.html[Open Liberty and Semeru Runtimes, cloud-native performance that matters].

The application supports several providers, you may use one of the following:

#### Github
    - Sign up and sign in to https://github.com.
    - Go to your https://github.com/settings/personal-access-tokens[Personal access tokens].
    - Generate a new token
    
#### Ollama
    - Download and install https://ollama.com/download[Ollama]
        * see the https://github.com/ollama/ollama/blob/main/README.md#ollama[README.md]
    - Pull the following model
        * `ollama pull llama3.2`

#### Mistral AI
    - Sign up and log in to https://console.mistral.ai/home.
    - Go to https://console.mistral.ai/api-keys[Your API keys].
    - Create a new key.

#### Hugging Face
    - Sign up and log in to https://huggingface.co.
    - Go to https://huggingface.co/settings/tokens[Access Tokens].
    - Create a new access token with `read` role.

To access the repository remotely, install https://git-scm.com/book/en/v2/Getting-Started-Installing-Git[Git] if you haven't already. You can clone the `sample-langchain4j` GitHub repository to your local machine by running the following command:

[#env_setup]
=== Environment setup

To run the application, navigate to the `sample-langchain4j/tools` directory:

[source]
----
cd sample-langchain4j/tools
----

Set the following environment variables:

[source]
----
export JAVA_HOME=<your Java 21 home path>
----

Set the appropriate key or url dependent on your provider:

If you are using Github, set with your GitHub API token:
[source]
----
export GITHUB_API_KEY=<your Github API token>
----

If you are using Ollama, set the url:
[source]
----
export OLLAMA_BASE_URL=http://localhost:11434
----

If you are using Mistral, set the Mistral API key:
[source]
----
export MISTRAL_AI_API_KEY=<your Mistral AI API key>
----

If you are using Hugging Face, set the hugging face token with the appropriate permissions:
[source]
----
export HUGGING_FACE_API_KEY=<your Hugging Face read token>
----

[#how_app_work]
== How does the application work?

The application demonstrates how to use the LangChain4j https://docs.langchain4j.dev/tutorials/tools#tool[tool] APIs, https://openliberty.io/docs/ref/feature/#cdi-4.0.html[Jakarta Contexts and Dependency Injection], https://openliberty.io/docs/latest/reference/feature/websocket-2.1.html[Jakarta WebSocket], and https://openliberty.io/docs/ref/feature/#mpConfig-3.0.html[MicroProfile Config] features.

[#create_tool]
=== Creating the tools

We first create functions that the AI is allowed to call by annotating it with `@Tool` and explaining the premise of the function. If there are any parameters, we annotate with `@P` to explain what it represents. This helps the AI distinguish when to call the tool and what to put as parameters. If the function returns, the AI will receive the output and can use it to customize its response back to the user.

The tools use the https://api.stackexchange.com/[Stack Overflow] along with JakartaEE methods to call the api and return the response to the AI. We created a few methods to search for different topics on Stack Overflow and a general search method.

See the {example-location}/src/main/java/io/openliberty/sample/langchain4j/StackOverflowTools.java[src/main/java/io/openliberty/sample/langchain4j/StackOverflowTools.java] file to learn more.
[source, java, role="no_copy"]
----
public class StackOverflowTools {
    ...
    private String clientSearch(String url) {
        Client client = ClientBuilder.newClient();
        Response response = client.target(url).request().get();
        String responseBody = response.readEntity(String.class);
        client.close();
        return responseBody;
    }

    @Tool("Multiple JakartaEE Questions on stackoverflow")
    public String searchJakartaEEQuestions() {
        logger.info("AI is searching stackoverflow for JakartaEE");
        return clientSearch(stackOverflowJakartaEE);
    }

    @Tool("Multiple MicroProfile Questions on stackoverflow")
    public String searchMicroProfileQuestions() {
        logger.info("AI is searching stackoverflow for MicroProfile");
        return clientSearch(stackOverflowMicroProfile);
    }

    @Tool("Multiple LangChain4j Questions on stackoverflow")
    public String searchLangChain4jQuestions() {
        logger.info("AI is searching stackoverflow for langchain4j");
        return clientSearch(stackOverflowLangChain4j);
    }

    @Tool("Search for questions and answers on stackoverflow")
    public String searchStackOverflow(@P("Question you are searching") String question) {
        String targetUrl = stackOverflowMethod + "&q=" + question + "&site=stackoverflow";
        return clientSearch(targetUrl);
    }
    ...
}
----

[#create_service]
=== Creating the LangChain4j AI service

We first inject the https://github.com/OpenLiberty/sample-langchain4j/blob/3564a2f12e4caea7f2ce627d337d2647eafa5d0e/tools/src/main/java/io/openliberty/sample/langchain4j/ChatAgent.java#L33-L34[StackOverFlowTools] class, then create the model with the https://github.com/OpenLiberty/sample-langchain4j/blob/3564a2f12e4caea7f2ce627d337d2647eafa5d0e/tools/src/main/java/io/openliberty/sample/langchain4j/ChatAgent.java#L58[appropriate parameters] so that it can use the tool.

We have a https://github.com/OpenLiberty/sample-langchain4j/blob/3564a2f12e4caea7f2ce627d337d2647eafa5d0e/tools/src/main/java/io/openliberty/sample/langchain4j/ChatAgent.java#L59[hallucinated tool name strategy] so that we can tell the AI in response when it tries to call a tool that does not exist, giving the AI another chance to hopefully call the correct tool.

See the {example-location}/src/main/java/io/openliberty/sample/langchain4j/ChatAgent.java[src/main/java/io/openliberty/sample/langchain4j/ChatAgent.java] file.
[source, java, role="no_copy"]
----
    public Assistant getAssistant() {
        ...
            ChatModel model = modelBuilder.getChatModel();
            assistant = AiServices.builder(Assistant.class)
                .chatModel(model)
                .tools(stackOverflowTools)
                .hallucinatedToolNameStrategy(toolExecutionRequest -> ToolExecutionResultMessage.from(
                    toolExecutionRequest, "Error: there is no tool with the following parameters called" + toolExecutionRequest.name()))
                .chatMemoryProvider(
                    sessionId -> MessageWindowChatMemory.withMaxMessages(MAX_MESSAGES))
                .build();
       ...
    }
----

Through the customized `Assistant` interface, the application can send messages to the LLM by its `chat()` method along with the system message telling the AI what its role and tasks are.

See the {example-location}/src/main/java/io/openliberty/sample/langchain4j/ChatAgent.java#L40-L49[src/main/java/io/openliberty/sample/langchain4j/ChatAgent.java#L40-L49] lines.
[source, java, role="no_copy"]
----
    interface Assistant {
        @SystemMessage("You are a coding helper, people will go to you for questions around coding. " +
            "You have ONLY four tools. " +
            "ONLY use the tools if NECESSARY. " +
            "ALWAYS follow the tool call parameters exactly and make sure to provide ALL necessary parameters. " +
            "Do NOT add more parameters than needed" + 
            "NEVER give the user unnecessary information. " + 
            "NEVER lie or make information up, if you are unsure say so.")
        String chat(@MemoryId String sessionId, @UserMessage String userMessage);
    }
----

[#communicate]
=== Communicating between the client and LLM

The application provides the interactive UI client for users to communicate with the LLM. Jakarta WebSocket enables two-way communication between the client and the `ChatService` service. Each client makes an HTTP connection to the service and send out the messages by the `send()` method.

See the {example-location}/src/main/webapp/toolChat.js[src/main/webapp/toolChat.js] file.
[source, java, role="no_copy"]
----

    const webSocket = new WebSocket(uri);
    ...
    function sendMessage() {
        ...
        var myMessage = document.getElementById('myMessage').value;
        ...
        webSocket.send(myMessage);
        ...
    }
----

The service receives the user messages through the WebSocket `onMessage()` method, forwards them to the LLM by calling the `ChatAgent.chat()` method, and then broadcasts the LLM answers back to the client session through the `sendObect()` method.

See the {example-location}/src/main/java/io/openliberty/sample/langchain4j/ChatService.java[src/main/java/io/openliberty/sample/langchain4j/ChatService.java] file.
[source, java, role="no_copy"]
----

    @OnMessage
    public void onMessage(String message, Session session) {
        ...
        try {
            ...
            answer = agent.chat(sessionId, message);
        } catch (Exception e) {
            ...
        }

        try {
            session.getBasicRemote().sendObject(answer);
        } catch (Exception e) {
            e.printStackTrace();
        }

    }
----
