== Adopting the MCP Java API in `mcpServer-1.0`

The link:https://modelcontextprotocol.io/docs/getting-started/intro[Model Context Protocol (MCP)] is an open standard that enables AI applications to access real-time data and business logic from external sources. The `mcpServer-1.0` feature lets application developers expose their application's tools and data for use in agentic AI workflows.

`mcpServer-1.0` now uses the link:https://central.sonatype.com/artifact/org.mcpjava/mcp-server-api[MCP Java API] (`org.mcpjava`), which is published on Maven Central. Previously, the types used to write MCP tools were in Open Liberty API packages.

Since this is an important change, a new blog post about using the MCP feature with examples using the new API has also been published. See link:{url-prefix}/blog/2026/08/25/mcp-tools.html[Getting started with mcpServer-1.0] for detailed instructions on how to get started with this feature.

NOTE: This is a breaking change. Existing code will not compile against the new API, but in most cases only the imports need to change.

=== Add the dependency to your project

For Maven, add the following to your `pom.xml`:

[source,xml]
----
<dependency>
    <groupId>org.mcpjava</groupId>
    <artifactId>mcp-server-api</artifactId>
    <version>1.0.0</version>
    <scope>provided</scope>
</dependency>
----

For Gradle, add the following to your `build.gradle`:

[source,gradle]
----
compileOnly("org.mcpjava:mcp-server-api:1.0.0")
----

=== Import changes

The core annotations and types have moved from `io.openliberty.mcp.*` to `org.mcpjava.server.*`:

[cols="2,2", options="header"]
|===
|Before (26.0.0.8-beta) |After (26.0.0.9-beta)

|`io.openliberty.mcp.tools.Tool`
|`org.mcpjava.server.tools.Tool`

|`io.openliberty.mcp.tools.ToolArg`
|`org.mcpjava.server.tools.ToolArg`

|`io.openliberty.mcp.tools.ToolResponse`
|`org.mcpjava.server.tools.ToolResponse`

|`io.openliberty.mcp.content.TextContent`
|`org.mcpjava.server.content.TextContent`

|`io.openliberty.mcp.content.ImageContent`
|`org.mcpjava.server.content.ImageContent`

|`io.openliberty.mcp.content.AudioContent`
|`org.mcpjava.server.content.AudioContent`

|`io.openliberty.mcp.content.ContentBlock`
|`org.mcpjava.server.content.ContentBlock`
|===

The following Liberty-specific types remain in their existing packages and are unchanged:

* `io.openliberty.mcp.tools.ToolCallException`
* `io.openliberty.mcp.tools.ToolManager`
* `io.openliberty.mcp.annotations.Schema`
* `io.openliberty.mcp.annotations.DefaultValueConverter`

=== Builder pattern for content types

One of the more visible differences in the MCP Java API is that content types are now created using builders rather than constructors. A `TextContent.of(...)` static factory is still available for simple cases, but richer types like `ImageContent` with annotations now use a builder:

[source,java]
----
// Before
ImageContent image = new ImageContent(data, "image/png");

// After — simple case
ImageContent image = ImageContent.of(data, "image/png");

// After — with annotations
ImageContent image = ImageContent.builder(data, "image/png")
                                 .setAnnotations(annotations)
                                 .build();
----

See the link:https://central.sonatype.com/artifact/org.mcpjava/mcp-server-api[MCP Java API Javadoc] for the full API reference.

NOTE: Although the MCP Java API includes types for prompts and resources, `mcpServer-1.0` currently only supports tools. The prompt and resource parts of the API are not functional in Liberty.

[#mcp_mbean_names]
== MCP metrics: MBean names now use individual JMX ObjectName keys

The MCP metrics MBeans introduced in 26.0.0.8-beta have been updated. Each `McpOperationStatisticsMXBean` and `McpSessionStatisticsMXBean` instance is now registered with its MCP attributes as individual keys in the JMX `ObjectName`, rather than encoded into a single opaque `name` value.

Before (26.0.0.8-beta):

[source]
----
WebSphere:type=McpOperation,name="mcpMethod:tools/call;rpcStatus:ok;netProto:HTTP"
----

After (26.0.0.9-beta):

[source]
----
WebSphere:type=McpOperation,mcpMethod=tools/call,rpcStatus=ok,netProto=HTTP,...
----

This makes it easier to filter or query for these MBeans based on their individual attribute values.

NOTE: This is a breaking change from 26.0.0.8-beta. If you have existing JMX queries or scripts written against the 26.0.0.8-beta MBean names, you will need to update them.

=== Bug fixes

==== MCP server endpoint URL log message updated

The info message that includes the MCP endpoint URL has been updated to include a message code. It now looks like this:

[source]
----
CWMCM0008I: The MCP server endpoint: http://localhost:9080/myApp/mcp
----

== Try it now

To try out these features, update your build tools to pull the Open Liberty All Beta Features package instead of the main release. To enable the MCP server feature, see link:{url-prefix}/blog/2026/08/25/mcp-tools.html[Getting started with mcpServer-1.0] for detailed instructions. Note that `mcpServer-1.0` requires Java SE 17 or later. The beta works with Java SE 25, Java SE 21, Java SE 17, Java SE 11, and Java SE 8.

        <runtimeArtifact>
          <groupId>io.openliberty.beta</groupId>
