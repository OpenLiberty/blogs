最新の大規模言語モデル (LLM) は、事前学習済みの知識からテキストを生成するだけではなく、"https://www.ibm.com/think/topics/tool-calling[tool calling]" と呼ばれる機能を通じて関数を実行することもできます。この機能により、LLM は外部システムと連携し、リアルタイムのデータにアクセスし、学習データの外側にあるアクションを実行できます。MicroProfile や Jakarta EE を利用する Java 開発者にとって、この機能の実装は LangChain4j ライブラリにより容易になりました。

この投稿では、LangChain4j を用いて Java アプリケーションにツール呼び出しを実装する方法を、Stack Overflow 検索機能を統合した実用例を通して示します。ツールを Java メソッドとして定義し、GitHub・Ollama・Mistral などの LLM プロバイダーに接続し、完全に動作するアプリケーションを構築する方法を学べます。

== LLM のツール呼び出しを理解する

ツール呼び出しは、LLM が外部関数をいつ、どの引数で呼び出すかを判断できるようにする仕組みです。ユーザーの質問に学習データを超える情報やアクションが必要だと判断した場合、LLM は適切な引数を含む構造化された関数呼び出しを生成し、曖昧な回答を試みるのではなく実際にツールを使います。

例えば、特定ライブラリに関する現在の Stack Overflow の課題を尋ねられた場合、LLM は学習データに基づく古い情報を返すのではなく、最新情報が必要だと認識し、適切な検索関数を正しいクエリで呼び出し、返ってきたデータを処理して回答を組み立てます。

Llama 3.1、GPT-4o、Claude 3 Opus、Mistral Large などのツール対応モデルは、標準化された JSON の関数呼び出しインターフェースを通じてこの機能をサポートします。本チュートリアルでは、GitHub Copilot、Ollama、Mistral AI で利用可能なモデルを使用します。

[#Java_LLMs_Tools]
== LangChain4j: Java による LLM ツール統合フレームワーク

LLM API に直接実装する場合、複雑な JSON スキーマの取り扱い、コンテキストウィンドウの管理、プロバイダーごとの実装差異への対応が必要です。LangChain4j は以下の機能を提供することで、これらの課題を解消します。

* 複数の LLM プロバイダーを横断する統一 Java インターフェース
* Java メソッドを LLM ツール化するためのシンプルなアノテーション
* パラメータのシリアライズと応答のパースを自動処理
* 会話コンテキストを維持するメモリ管理
* 幻覚的なツール呼び出しに対するエラーハンドリング

https://github.com/langchain4j/langchain4j[LangChain4j] を使えば、LLM 統合の詳細ではなくビジネスロジックに集中できます。`@Tool` や `@P` のようなシンプルなアノテーションにより、任意の Java メソッドを LLM に公開でき、既存のエンタープライズサービスと AI 機能を統合したい MicroProfile/Jakarta EE アプリケーションで特に有用です。

image::/img/blog/langchain4j.png[langchain4j GitHub README image,width=70%,align="center"]

[#using_Langchain4j]
== MicroProfile/Jakarta EE と LangChain4j の統合

LangChain4j は標準の CDI メカニズムを通じて、MicroProfile および Jakarta EE アプリケーションにシームレスに統合できます。実装する主な要素は次のとおりです。

* **ツール定義** - LLM が呼び出せるよう `@Tool` で注釈した Java メソッド
* **AI サービスインターフェース** - アプリケーションと LLM のやり取りを定義
* **モデル設定** - 選択した LLM プロバイダーへの接続設定
* **Jakarta WebSocket エンドポイント** - ユーザーと AI のリアルタイム通信

以下のサンプルアプリケーションは、Stack Overflow 検索アシスタントを実装し、これらの要素をすべて実演します。完全なコードは https://github.com/OpenLiberty/sample-langchain4j/tree/main/tools[sample-langchain4j/tools] リポジトリで参照できます。

さらに多くの例は、公式の https://github.com/langchain4j/langchain4j-examples[langchain4j-examples] も参照してください。

[#how_app_work]
== アプリケーションはどのように動作するか

このアプリケーションのアーキテクチャは、ツール呼び出し機能を備えた AI アシスタントを実現する 4 つの主要コンポーネントで構成されます。

* **ツール実装** (`StackOverflowTools.java`) - LLM から呼び出せるよう注釈した Java メソッド
* **AI サービス** (`ChatAgent.java`) - LLM の設定とインターフェース公開
* **WebSocket エンドポイント** (`ChatService.java`) - クライアントとのリアルタイム通信
* **フロントエンド** (`toolChat.js`, `toolChat.html`) - ユーザーインターフェース

image::/img/blog/langchain4jDiagram.png[Architectural diagram,width=70%,height=70%,align="center"]

ユーザーが WebSocket 経由でメッセージを送ると、次の手順で処理されます。

1. `ChatService` エンドポイントがメッセージを受信
2. `ChatAgent` に転送され、設定済み LLM に送信
3. LLM がツール呼び出しの必要性を判断
4. 必要に応じて、適切な引数を含むツール呼び出しを生成
5. LangChain4j が対応する Java メソッドを実行
6. ツールの結果が LLM に返され、応答に取り込まれる
7. 最終応答が WebSocket を通じてクライアントに返送

この実装では、https://api.stackexchange.com/[Stack Overflow API] を利用して LLM の機能を拡張します。技術的な質問で最新の Stack Overflow データが有用な場合、LLM は適切な検索メソッドを呼び出します。

1. 検索は Stack Exchange API で関連する質問を取得
2. 各質問のトップ回答を取得
3. 結果を整形して LLM に返却
4. LLM が返却データを統合して分かりやすい応答に合成

[#create_tool]
=== ツール実装

ツールの中核は、LangChain4j の `@Tool` と `@P` アノテーションで注釈した Java メソッドで実装します。

[source,java]
----
@Tool("Search for questions and answers on stackoverflow")
public ArrayList<String> searchStackOverflow(@P("Question you are searching") String question) throws Exception {
    logger.info("AI called the searchStackOverflow Tool with question: " + question);
    String targetUrl = stackOverflowMethod + "&q=" + question;
    return questionAndAnswer(targetUrl);
}
----

これらのアノテーションは次の重要な役割を持ちます。

* `@Tool` は、いつそのツールを使うべきか、どの機能を提供するか、期待される出力形式は何かを LLM に伝えます。
* `@P` は、各パラメータの意味を記述し、LLM が必要な情報を提供し、パラメータを正しく整形し、ユーザーの質問から関連情報を抽出できるようにします。

実装では標準の Jakarta EE HTTP Client API を使用して Stack Exchange API と通信します。

[source,java]
----
private ArrayList<String> questionAndAnswer(String url) throws Exception {
    ArrayList<String> questionAnswer = new ArrayList<>();
    for (Map<String, Object> data : clientSearch(url)) {
        String topAnswer = clientSearch(String.format(findAnswer, data.get("question_id")))
                                .get(0).get("body").toString();
        questionAnswer.add(
            "Link: " + "https://stackoverflow.com/questions/" + data.get("question_id") + 
            " Problem: " + data.get("body") +
            " Answer: " + topAnswer
        );
    }
    return questionAnswer;
}
----

このメソッドは、LLM が処理しやすい形式で結果を返し、必要な文脈（質問、回答、リンク）をすべて含み、安定して扱える構造を保ちます。

ツールを実装する際の推奨事項:

* ツールメソッドは単一責務に絞る
* LLM が扱いやすい構造化データを返す
* 戻り値に十分なコンテキストを含める
* 機能を明確に説明する注釈を付ける
* 例外を適切に処理して LLM の混乱を防ぐ

[#create_service]
=== AI サービス実装

`ChatAgent` クラスは、アプリケーションと LLM の橋渡しを行います。プロバイダー設定、ツール登録、会話メモリ管理、幻覚的ツール呼び出しのエラーハンドリングを担当します。

LangChain4j のビルダーパターンで中核設定を行います。

[source,java]
----
public Assistant getAssistant() {
    ChatModel model = modelBuilder.getChatModel();
    assistant = AiServices.builder(Assistant.class)
        .chatModel(model)
        .tools(stackOverflowTools)
        .hallucinatedToolNameStrategy(toolExecutionRequest -> 
            ToolExecutionResultMessage.from(toolExecutionRequest, 
                "Error: there is no tool with the following parameters called " + 
                toolExecutionRequest.name()))
        .chatMemoryProvider(
            sessionId -> MessageWindowChatMemory.withMaxMessages(MAX_MESSAGES))
        .build();
    return assistant;
}
----

主な設定要素は以下です。

* `tools()` はツールクラスを LLM に登録
* `hallucinatedToolNameStrategy` は存在しないツール呼び出し時の優雅なエラー処理（LLM で起こりがち）
* `chatMemoryProvider` は会話履歴の保持を設定。複数メッセージにわたる文脈維持に必須

AI サービスは、LangChain4j アノテーション付きの Java インターフェースとして公開されます。

[source,java]
----
interface Assistant {
    @SystemMessage("You are a coding helper, people will go to you for questions around coding. " +
        "You have ONLY four tools. " +
        "ONLY use the tools if NECESSARY. " +
        "ALWAYS follow the tool call parameters exactly and make sure to provide ALL necessary parameters. " +
        "Do NOT add more parameters than needed" + 
        "NEVER give the user unnecessary information. " + 
        "NEVER lie or make information up, if you are unsure say so.")
    String chat(@MemoryId String sessionId, @UserMessage String userMessage);
}
----

`@SystemMessage` は、ツール使用のタイミングや方法、役割、制約、エラー処理の期待を LLM に明確に指示します。

`@MemoryId` はユーザーごとの会話履歴を分離し、`@UserMessage` はユーザー入力を表すパラメータであることを示します。

[#communicate]
=== WebSocket によるクライアントと LLM の通信

このアプリケーションは Jakarta WebSocket を使って、クライアントと AI サービスのリアルタイム通信を実現します。これは従来の REST エンドポイントに対して次の利点があります。

* **リアルタイム対話** - ポーリング不要で即応答
* **永続接続** - 複数メッセージでもオーバーヘッドを軽減
* **セッション管理** - 会話状態の追跡が容易

サーバー側実装は標準の Jakarta WebSocket アノテーションを用います。

[source,java]
----
@ServerEndpoint(value = "/toolchat", encoders = { ChatMessageEncoder.class })
public class ChatService {
    @Inject
    ChatAgent agent = null;
    
    @OnMessage
    public void onMessage(String message, Session session) {
        ...
        
        try {
            answer = agent.chat(sessionId, message);
        } catch (Exception e) {
            ...
        }

        try {
            session.getBasicRemote().sendObject(answer);
        } catch (Exception e) {
            ...
        }
    }
	// Other WebSocket lifecycle methods...   
}
----

実装のポイント:

* 各 WebSocket 接続は一意の `sessionId` を持ち、会話の文脈維持に利用
* 堅牢なエラーハンドリングにより、問題発生時も適切に通知
* 非同期 WebSocket は、LLM の処理時間の長さに自然に対応

クライアント側 JavaScript は WebSocket 接続を確立し、メッセージ送受信を処理します。

[source,javascript]
----
const webSocket = new WebSocket(uri);

webSocket.onmessage = function(event) {
    // Display AI response
    displayMessage(event.data, "ai");
};

function sendMessage() {
    var myMessageRow = document.createElement('tr');
    var myMessage = document.getElementById('myMessage').value;
    myMessageRow.innerHTML = '<td><p class=\"my-msg\">' + myMessage + '</p></td>' +
                                '<td>' + getTime() + '</td>';
    messagesTableBody.appendChild(myMessageRow);
    messagesTableBody.appendChild(thinkingRow);
    webSocket.send(myMessage);
    document.getElementById('myMessage').value = "";
}
----

この双方向チャネルにより、ユーザーは反応の良いチャット体験を得られ、裏側ではツール呼び出しが透過的に行われます。

== まとめ: ツール呼び出しで AI 対応の Java アプリを構築

本チュートリアルでは、LangChain4j を用いて MicroProfile/Jakarta EE アプリに LLM のツール呼び出し機能を実装する方法を紹介しました。ここで示した実装パターンに従えば、単なるテキスト生成を超えた AI 機能を自身のアプリに拡張できます。

取り上げた主要な技術ポイント:

* `@Tool` と `@P` による Java メソッドの公開
* 適切なモデル設定とツール登録を伴う LangChain4j のセットアップ
* 幻覚的ツール呼び出しに対する対処戦略
* WebSocket を使ったユーザーと AI のリアルタイム通信
* 複数やり取りにまたがる会話コンテキストの維持

このアプローチの利点:

* **関心の分離** - ビジネスロジックは標準的な Java メソッドにとどめ、AI 統合は分離
* **プロバイダーの柔軟性** - 同一コードで複数の LLM プロバイダー（GitHub、Ollama、Mistral）に対応
* **エンタープライズ統合** - 既存の Jakarta EE/MicroProfile アプリに無理なく組み込み
* **拡張性** - 要件に合わせて新しいツールを容易に追加

応用の方向性:

* アプリケーションのデータベースと連携するツール
* 業務プロセスやワークフローを開始するツール
* 社内ナレッジベースやドキュメントにアクセスするツール
* 特定業界に特化したドメイン固有ツール

最新の LLM と Jakarta EE の企業向け機能を組み合わせることで、アクション実行・リアルタイムデータアクセス・より価値の高い応答の提供など、強力なインテリジェントアプリケーションを構築できます。
