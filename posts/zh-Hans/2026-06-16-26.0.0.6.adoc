== 使用 26.0.0.6 开发和运行应用程序

如果您使用 link:{url-prefix}/guides/maven-intro.html[Maven]，请在 `pom.xml` 文件中包含以下内容：

[source,xml]
----
<plugin>
    <groupId>io.openliberty.tools</groupId>
    <artifactId>liberty-maven-plugin</artifactId>
    <version>3.12.0</version>
</plugin>
----

或者对于 link:{url-prefix}/guides/gradle-intro.html[Gradle]，请在 `build.gradle` 文件中包含以下内容：

[source,gradle]
----
buildscript {
    repositories {
        mavenCentral()
    }
    dependencies {
        classpath 'io.openliberty.tools:liberty-gradle-plugin:4.0.0'
    }
}
apply plugin: 'liberty'
----

== 此版本中修复的重要错误


我们花了一些时间修复错误。以下部分描述了此版本中解决的问题。如果您感兴趣，这里是 link:https://github.com/OpenLiberty/open-liberty/issues?q=label%3Arelease%3A26006+label%3A%22release+bug%22[26.0.0.6 中修复的错误的完整列表]。

* link:https://github.com/OpenLiberty/open-liberty/issues/34863[featureUtility 在 server.xml 格式错误时以返回代码 0 退出]
* link:https://github.com/OpenLiberty/open-liberty/issues/34857[应用程序启动期间 EJBRemoteRuntimeImpl 中 AlreadyBound 异常的 FFDC]
* link:https://github.com/OpenLiberty/open-liberty/issues/34802[修复 featureUtility 的 AES 加密问题]
* link:https://github.com/OpenLiberty/open-liberty/issues/34773[未设置 JAVA_HOME 时，Windows 上未加载 java9.options]
* link:https://github.com/OpenLiberty/open-liberty/issues/34573[io.openliberty.mpTelemetry.2.0.thirdparty 缺少指标 API（以及其他一些）。稳定的 io.openliberty.io.opentelemetry.2.1 jar 也是如此]
* link:https://github.com/OpenLiberty/open-liberty/issues/34288[由于 HTTP/2 连接中出现的竞争条件，在 Socket 读取期间 TCP 通道层中发生 NPE]

* link:https://github.com/OpenLiberty/open-liberty/issues/31630[当多个线程尝试关闭同一连接流时，HTTP/2 间歇性服务器静默失败]
* link:https://github.com/OpenLiberty/open-liberty/issues/30564[Windows 服务的停止命令中未使用 WINDOWS_SERVICE_STOP_TIMEOUT]

== 自上一版本以来的新指南和更新指南
