== MCP Server (`mcp-1.0`) is now GA

The link:https://modelcontextprotocol.io/docs/getting-started/intro[Model Context Protocol (MCP)] is an open standard that enables AI applications to access real-time data and business logic from external sources. The `mcp-1.0` feature lets you expose your Liberty application's tools and data for use in agentic AI workflows.

After several beta releases (starting from `25.0.0.12-beta` as `mcpServer-1.0`), the feature is now generally available in Open Liberty 26.0.0.9. For full documentation on how to declare tools, configure the MCP server, secure your endpoints, and connect AI clients, see the link:https://openliberty.io/blog/2026/08/25/mcp-tools.html[Expose your Liberty business logic as AI tools] blog post and the link:https://openliberty.io/docs/latest/liberty-mcp-server.html[`mcp-1.0` feature documentation].

NOTE: `mcp-1.0` requires Java SE 17 or later.

=== Changes since 26.0.0.9-beta

==== Feature renamed from `mcpServer-1.0` to `mcp-1.0`

The most important change for this release is that the feature name has changed from `mcpServer-1.0` to `mcp-1.0`, and the `server.xml` configuration element has changed from `<mcpServer>` to `<mcp>`.

Update your `server.xml` to use the new name:

[source,xml]
----
<featureManager>
    <feature>mcp-1.0</feature>
</featureManager>

<application location="my-app.war">
    <mcp path="/custom-mcp"/>
</application>
----

The reason for the rename is that most Liberty features relate to server functionality without including "server" in their name, and `mcpServer-1.0` could be confused with "an MCP server for interacting with Liberty" rather than "an API for writing and deploying MCP servers on Liberty".

==== API package change: `io.openliberty.mcp.*` → `org.mcpjava.server.*`

If you are migrating from 26.0.0.8-beta or earlier, the core annotations and types moved from `io.openliberty.mcp.*` to `org.mcpjava.server.*`. Update your Maven dependency and your imports:

[source,xml]
----
<dependency>
    <groupId>org.mcpjava</groupId>
    <artifactId>mcp-server-api</artifactId>
    <version>1.0.0</version>
    <scope>provided</scope>
</dependency>
----

The following Liberty-specific types remain unchanged:

* `io.openliberty.mcp.tools.ToolCallException`
* `io.openliberty.mcp.tools.ToolManager`
* `io.openliberty.mcp.annotations.Schema`
* `io.openliberty.mcp.annotations.DefaultValueConverter`

==== MCP metrics MBean names now use individual JMX ObjectName keys

Each `McpOperationStatisticsMXBean` and `McpSessionStatisticsMXBean` instance is now registered with its MCP attributes as individual keys in the JMX `ObjectName`.

Before (26.0.0.8-beta):

[source]
----
WebSphere:type=McpOperation,name="mcpMethod:tools/call;rpcStatus:ok;netProto:HTTP"
----

After (26.0.0.9 GA):

[source]
----
WebSphere:type=McpOperation,mcpMethod=tools/call,rpcStatus=ok,netProto=HTTP,...
----

If you have existing JMX queries written against the 26.0.0.8-beta MBean names, update them to use the individual-key format.

=== New capabilities in this GA release

==== DNS rebinding attack protection

The `mcp-1.0` feature now guards against DNS rebinding attacks on locally running MCP servers, as required by the link:https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#security-warning[MCP specification]. When an MCP server receives a request from a loopback address, it validates the `Origin` header if one is present. No configuration is required; this protection is enabled by default.

==== `@MetaField` support on tool methods

Tool methods can now be annotated with `@MetaField` from the MCP Java API to add data to the `_meta` object in the tool description returned in `tools/list` responses. This allows you to attach vendor-defined metadata to individual tool descriptions.

==== `outputSchemaFrom` on `@Tool`

The `@Tool` annotation now supports the `outputSchemaFrom` attribute. When `structuredContent = true`, this allows you to specify a different class to use for generating the output schema, independent of the method's return type.

==== Warnings for unsupported MCP annotations

If your application uses MCP Java API annotations that are not yet supported by `mcp-1.0`, such as `@Prompt`, `@Resource`, `@ResourceTemplate`, `@CompletePrompt`, or `@CompleteResourceTemplate`, Liberty now logs a warning. The application still starts and any `@Tool`-annotated methods continue to work; only the unsupported annotations are ignored.

==== OAuth 2.0 protected resource metadata is now GA

Support for serving link:https://datatracker.ietf.org/doc/html/rfc9728[OAuth 2.0 Protected Resource Metadata] (RFC 9728) is also now generally available. When `protectedResourceMetaDataEnabled="true"` is configured on `openidConnectClient`, Liberty serves the protected resource metadata document at `/.well-known/oauth-protected-resource`. This allows MCP clients to automatically discover the correct authorization server to use when accessing protected MCP endpoints, following the link:https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization[MCP authorization flow].

== Notable bugs fixed in this release

We've spent some time fixing bugs. The following sections describe just some of the issues resolved in this release. If you're interested, here's the link:https://github.com/OpenLiberty/open-liberty/issues?q=label%3Arelease%3A26009+label%3A%22release+bug%22[full list of bugs fixed in 26.0.0.9].

* link:https://github.com/OpenLiberty/open-liberty/issues/35314[MCP: Improve error handling for notification messages] - JSON-RPC notifications that resulted in an exception caused an `IllegalArgumentException` because the server incorrectly attempted to send an error response to a notification (which has no `id`). Notifications are now handled silently in line with the JSON-RPC specification.
* link:https://github.com/OpenLiberty/open-liberty/issues/35564[Potential memory leak with mcp-1.0 under app load] - A memory leak was identified under sustained load and has been resolved.
