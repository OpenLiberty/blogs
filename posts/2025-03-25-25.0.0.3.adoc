== New library configuration for a path that target a file or a folder


A link:https://openliberty.io/docs/latest/reference/config/library.html[library configuration] in liberty can be configured with a list of `file`, `folder` or `fileset` configuration elements. The `file` and `folder` configurations require you to know if the target of the configuration is a file (e.g. JAR) or a folder ahead of time. The `fileset` configuration will only match targets that are files (e.g. JARs) and will ignore folders. For the liberty 25.0.0.3 release a new configuration has been added for `library` named `path`.  A `path` configuration may target a file (e.g. JAR) or a folder. You no longer need to know ahead of time what the target type is because the `path` configuration will accept both a file or a folder target. For example, consider the following library configuration for `someLib`:

```xml
    <library id="someLib">
       <!-- path to a jar -->
       <file name="libs/lib1.jar"/>
       <!-- path to a folder -->
       <folder dir="libs/lib2folder"/>
    </library>
```
This configuration for `someLib` can now use `path` instead:
```xml
    <library id="someLib">
       <!-- path to a jar -->
       <path name="libs/lib1.jar"/>
       <!-- path to a folder -->
       <path name="libs/lib2folder"/>
    </library>
```

Enable on server
```
To enable FIPS 140-3 follow the instructions from the IBM JDK 8 blog post link:https://www.ibm.com/docs/en/sdk-java-technology/8?topic=guide-fips-140-3[here. ]. Specifically, the following system properties should be set (for example in the jvm.options file).
        -Xenablefips140-3
        -Dcom.ibm.jsse2.usefipsprovider=true
        -Dcom.ibm.jsse2.usefipsProviderName=IBMJCEPlusFIPS
    Where can they find out more about this specific update (eg Open Liberty docs, Javadoc) and/or the wider technology?
        IBM JDK 8 link:https://www.ibm.com/docs/en/sdk-java-technology/8?topic=guide-fips-140-3[doc]
        link:https://docs-draft-openlibertyio.mqj6zf7jocq.us-south.codeengine.appdomain.cloud/docs/latest/enable-fips.html[Open Liberty docs]
```
Enable on command line to generate LTPA keys
```
To enable FIPS 140-3 to create LTPA keys using the securityUtility command add the JVM arguments into environment JVM_ARGS before executing the command. 

export JVM_ARGS="-Dcom.ibm.jsse2.usefipsprovider=true -Xenablefips140-3 -Dcom.ibm.jsse2.usefipsProviderName=IBMJCEPlusFIPS"
```
TLS
```
FIPS 140-3 supports only the TLS 1.2 and 1.3 protocols. 
```

LTPA
```
With FIPS 140-3 enabled, the LTPA keys use FIPS 140-3 approved cryptographic algorithms. The server can only load the LTPA keys generated using FIPS 140-3 approved algorithms. For LTPA Single SIgn On (SSO) to work, users must configure all servers to use FIPS 140-3.  For more information see (link to our LTPA doc)
```

Creating LTPA keys with FIPS 140-3 enabled at server start

```
With FIPS 140-3 enabled via jvm.options, server start will generate the ltpa.keys file with FIPS approved algorithms if there is no existing ltpa.keys file. If the ltpa.keys file already exits, delete it and restart the server after configuring FIPS 140-3.
```

Creating a new FIPS key using securityUtility: 

```
One can also create the LTPA keys using the securityUtulity command's createLTPAKeys option. To generate the LTPA keys with FIPS 140-3 approved algorithms, configure FIPS 140-3 using the JVM_ARGS environment variable and run the command.

export JVM_ARGS="-Dcom.ibm.jsse2.usefipsprovider=true -Xenablefips140-3 -Dcom.ibm.jsse2.usefipsProviderName=IBMJCEPlusFIPS"

securityUtility createLTPAKeys --password=mypassword --passwordEncoding=aes
```

Updates to audit logging encryption and signing
```
Audit logging encryption and signing use updated crypto algorithms. Logs generated with audit will be updated regardless of FIPS 140-3 being enabled. Users with audit logs from before 25.0.0.3 will need to use the auditUtility from a backlevel version of liberty to read them.
```

AES and HASH secrets
```
Going forward all new AES and HASH secrets in liberty are updated to use AES 256 / PBKDF2WithHmacSHA512 regardless of FIPS 140-3 being enabled. With FIPS 140-3 disabled, old secrets will be tolerated. With FIPS 140-3 enabled, old secrets must  be regenerated using securityUtility. 
```
