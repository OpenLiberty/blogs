[#quiesce_timeout]
== Configurable quiesce timeout on the server element

When you stop an Open Liberty server, it enters a quiesce phase—a grace period during which it waits for active work to finish before the JVM exits. During this phase, Liberty notifies registered shutdown listeners, allowing features to drain connections and complete in-flight requests, and then waits for any remaining active threads in the executor service to finish. Previously, this grace period was hardcoded to 30 seconds with no way to adjust it. For teams running workloads with long-lived requests—such as batch jobs, large file transfers, or complex transactions—30 seconds was often insufficient, leaving work abruptly interrupted at shutdown.

You can now configure the quiesce grace period to any value of 30 seconds or greater by using the `quiesceTimeout` attribute on the `<server>` element in your `server.xml` file.

=== Two-stage shutdown sequence

The configured timeout governs a two-stage shutdown sequence:

. *Pre-phase listeners* — Liberty first notifies pre-phase `ServerQuiesceListener` components, such as the channel framework, which stops inbound network connections. These listeners have the full configured timeout available to them.
. *Default-phase listeners and thread drain* — Liberty then notifies default-phase listeners, which drain in-flight application work, and waits for active threads in the shared executor service to finish. These share whatever time remains from the original budget.

[NOTE]
====
If pre-phase listeners consume more than half of the configured timeout, Liberty grants the default-phase listeners a fresh window equal to half the configured timeout, rather than the remaining time. This means the actual elapsed shutdown time can be up to 1.5× the configured value. If your application code must complete within a strict wall-clock deadline at shutdown, set `quiesceTimeout` conservatively enough to account for this behaviour.
====

=== Configuration

Add the `quiesceTimeout` attribute to the `<server>` element in your `server.xml` file:

[source,xml]
----
<server quiesceTimeout="2m">
    <!-- your existing configuration -->
</server>
----

The value uses Liberty's standard duration syntax — specify a positive integer followed by a time unit: `h` (hours), `m` (minutes), `s` (seconds), or `ms` (milliseconds). You can also combine units:

[source,xml]
----
<!-- 2 minutes -->
<server quiesceTimeout="2m">

<!-- 90 seconds — two equivalent forms -->
<server quiesceTimeout="1m30s">
<server quiesceTimeout="90s">

<!-- plain integer is interpreted as seconds -->
<server quiesceTimeout="120">
----

The minimum allowed value is `30s`. Values less than this threshold, or values that cannot be parsed, fall back to the default of 30 seconds and log warning message `CWWKG0111W`.

The timeout can be updated dynamically. If you change it in `server.xml` while the server is running, the next shutdown automatically uses the new value without requiring a server restart.

[NOTE]
====
*For Beta users:* In the beta release, this attribute was configured on the `<executor>` element (for example, `<executor quiesceTimeout="1m30s"/>`). In 26.0.0.11, it is configured on `<server>` element. Update your `server.xml` accordingly.
====

=== Shutdown log messages

When the server begins quiescing, it logs an audit message `CWWKE1100I`, which displays the configured timeout:

----
CWWKE1100I: Waiting for up to 120 seconds for the server to quiesce.
----

On a clean shutdown, message `CWWKE1101I` follows:

----
CWWKE1101I: Server quiesce complete.
----

If the timeout expires before all listeners and threads finish, Liberty proceeds with shutdown and logs the following messages:

----
CWWKE1102W: The quiesce operation did not complete. The server will now stop.
CWWKE1106W: 2 shutdown operations did not complete during the quiesce period. ...
CWWKE1107W: A total of 3 threads did not complete during the quiesce period.
----

`CWWKE1102W` is the signal to increase `quiesceTimeout`. The accompanying `CWWKE1106W` and `CWWKE1107W` messages identify specifically which listeners and how many threads were still running, providing the information needed to choose an appropriate value.

For more information, see the link:https://openliberty.io/docs/latest/reference/config/server-configuration-overview.html[Liberty server element configuration reference] and link:https://openliberty.io/docs/latest/server-configuration-overview.html[Configuring Liberty server shutdown].


[#form_login_redirect]
== Additional validation for form login error page redirects

Open Liberty now blocks form login error page redirects to external hosts unless the target host is listed in the `wasReqURLRedirectDomainNames` attribute of the `<webAppSecurity/>` element. This validation is consistent with the existing check that is applied to `WASReqURL` redirects.

This change applies whenever you specify a form login error page. You can configure this error page by using either the `error_page` request parameter or the `loginErrorURL` attribute of the `<webAppSecurity/>` element in your `server.xml` file. The host in the error page URL must match either the host of the current login request or a host that is listed in the `wasReqURLRedirectDomainNames` attribute of the `<webAppSecurity/>` element. Otherwise, the redirect to an external host is blocked, and Liberty logs the error message `CWWKS9134E`. To allow the redirect, add the trusted host to this attribute.

For more information, see the link:https://openliberty.io/docs/latest/reference/config/webAppSecurity.html[`webAppSecurity`] configuration element.

== Develop and run your apps using 26.0.0.11

If you're using link:{url-prefix}/guides/maven-intro.html[Maven], include the following in your `pom.xml` file:

[source,xml]
----
<plugin>
    <groupId>io.openliberty.tools</groupId>
    <artifactId>liberty-maven-plugin</artifactId>
    <version>3.12.4</version>
</plugin>
----

Or for link:{url-prefix}/guides/gradle-intro.html[Gradle], include the following in your `build.gradle` file:

[source,gradle]
----
buildscript {
    repositories {
        mavenCentral()
    }
    dependencies {
        classpath 'io.openliberty.tools:liberty-gradle-plugin:4.0.3'
    }
}
apply plugin: 'liberty'
----

Or if you're using link:{url-prefix}/docs/latest/container-images.html[container images]:

[source]
----
FROM icr.io/appcafe/open-liberty
----

Or take a look at our link:{url-prefix}/start/[Downloads page].

If you're using link:https://plugins.jetbrains.com/plugin/14856-liberty-tools[IntelliJ IDEA], link:https://marketplace.visualstudio.com/items?itemName=Open-Liberty.liberty-dev-vscode-ext[Visual Studio Code] or link:https://marketplace.eclipse.org/content/liberty-tools[Eclipse IDE], you can also take advantage of our open source link:https://openliberty.io/docs/latest/develop-liberty-tools.html[Liberty developer tools] to enable effective development, testing, debugging and application management all from within your IDE.
