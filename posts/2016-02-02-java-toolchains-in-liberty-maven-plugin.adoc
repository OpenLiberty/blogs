As the Java ecosystem evolves, developers frequently face "version mismatch" challenges. Modern development often requires balancing the requirements of your build tool, your application source code, and your target runtime environment.

Starting with **liberty-maven-plugin version 3.12.0**, we officially support **Maven Toolchains**. This integration allows you to decouple the JDK used to run Maven from the JDK used to run your Open Liberty server, ensuring a consistent and automated development experience.

'''

== Why Use Maven Toolchains?

The need for toolchains has moved from a "nice-to-have" to a necessity for many modern workflows:

* **Build Tool Requirements (Maven 4):** The upcoming Maven 4 requires Java 17 or higher to run. If you want to leverage the latest Maven features but your application is targeted for an older JDK (like Java 8 or 11), toolchains allow you to run Maven on Java 17 while the Liberty plugin executes your server and tests on the required target JDK.
* **Environment Consistency:** It eliminates the "works on my machine" syndrome. By defining the JDK in the project configuration rather than relying on a local `JAVA_HOME` environment variable, every developer and CI/CD agent uses the exact same environment.
* **Vendor Flexibility:** If your production environment uses a specific distribution (like IBM Semeru or Eclipse Temurin), toolchains ensure you develop and test against that specific vendor’s JVM without affecting your global system settings.

'''

== Internal Mechanics: How Liberty Honors Toolchains

When you configure a toolchain, the `liberty-maven-plugin` doesn't just pass a flag to Maven; it internally reconfigures how it interacts with the Open Liberty runtime across **all** plugin goals.



By detecting the toolchain JDK, the plugin directs the following core operations to use the toolchain’s Java executable instead of the system default:

* **Server Lifecycle Goals:** Goals such as `liberty:start`, `liberty:run`, and `liberty:stop` invoke the server processes using the toolchain JVM.
* **Development Goals:** The `liberty:dev` goal uses the toolchain to monitor, recompile, and refresh the application in real-time.
* **Packaging and Assembly:** Goals like `liberty:package`, `liberty:create`, and `liberty:install-feature` use the toolchain to ensure any internal JVM-based logic (like feature resolution) is consistent with your target runtime.
* **Testing and Verification:** Goals such as `liberty:test-start` and `liberty:test-stop` ensure the testing environment matches the server environment.

'''

== Supporting Maven Toolchains in Liberty

=== Step 1: Create a Global `toolchains.xml`
Maven toolchains are managed globally. Create a `toolchains.xml` file in your `~/.m2/` directory. For a deep dive into the schema, see the link:https://maven.apache.org/guides/mini/guide-using-toolchains.html[Official Maven Toolchains Guide].

**Example: Multiple JDK Vendors**
[source,xml]
----
<?xml version="1.0" encoding="UTF-8"?>
<toolchains>
  <toolchain>
    <type>jdk</type>
    <provides>
      <version>17</version>
      <vendor>temurin</vendor>
    </provides>
    <configuration>
      <jdkHome>/opt/java/temurin-17</jdkHome>
    </configuration>
  </toolchain>
</toolchains>
----

=== Step 2: Set the `jdkToolchain` in Liberty Maven Plugin
Add the `jdkToolchain` parameter to your `liberty-maven-plugin` configuration in the `pom.xml`.

[source,xml]
----
<plugin>
    <groupId>io.openliberty.tools</groupId>
    <artifactId>liberty-maven-plugin</artifactId>
    <version>3.12.0</version>
    <configuration>
        <jdkToolchain>
            <version>17</version>
            <vendor>temurin</vendor>
        </jdkToolchain>
    </configuration>
</plugin>
----

'''

== Deep Dive: Toolchains in Dev Mode

In **Dev Mode** (`mvn liberty:dev`), the plugin ensures that the specified JDK is used for the entire "inner loop" of development. Internally, the plugin's `DevMojo` identifies the toolchain and ensures it is used for both the server runtime and the compilation of source and test classes.

=== Precedence and Testing Integration
If your project also defines toolchains for the `maven-surefire-plugin` or `maven-failsafe-plugin`, the Liberty plugin will handle conflicts to ensure your tests don't run on a different JVM than your server.

[IMPORTANT]
====
If a `jdkToolchain` is defined in both the Liberty plugin and the Surefire/Failsafe plugins, the **Liberty Maven Plugin configuration takes higher precedence**.
====

**Console Output Examples:**
If the Liberty plugin overrides a toolchain configured in another plugin, it will log a warning:

`[WARNING] The jdkToolchain configuration in liberty-maven-plugin overrides the jdkToolchain configuration in maven-surefire-plugin.`

When starting Dev Mode, the plugin confirms the toolchain being used:

`[INFO] Using jdkToolchain: JDK[/opt/java/temurin-17]`

'''

== Troubleshooting Toolchain Issues

If the Liberty plugin cannot find a matching toolchain based on your `pom.xml` configuration, it will default to the system's `JAVA_HOME`. Here is how to diagnose issues:

1. **Verify the Match:** Ensure the `<provides>` block in your `toolchains.xml` exactly matches the `<jdkToolchain>` block in your `pom.xml`. These are simple string matches.
2. **Check File Location:** Ensure `toolchains.xml` is in the correct directory (`~/.m2/toolchains.xml`).
3. **Check Plugin Logs:** If the plugin cannot find the requested toolchain, it will log an info message:
+
[source,text]
----
[INFO] The jdkToolchain configuration will be ignored because the specified toolchain could not be found.
----
4. **Use Maven Debug Mode:** Run your command with `-X` (e.g., `mvn liberty:dev -X`) to see exactly how Maven is searching for and matching toolchains.

'''

== Verify the Configuration

Check the `messages.log` file in `target/liberty/wlp/usr/servers/defaultServer/logs/`. The header will indicate the toolchain's Java version:

**Sample `messages.log` output:**
[source,text]
----
********************************************************************************
product = Open Liberty 25.0.0.12
java.home = /opt/java/temurin-17/Contents/Home
java.version = 17.0.12
********************************************************************************
----

== Conclusion

By honoring JDK toolchains across all goals—from `liberty:create` to `liberty:dev`—the Liberty Maven Plugin ensures that your build, runtime, and test environments are perfectly aligned. Whether you are moving to Maven 4 or managing complex legacy requirements, toolchains provide the flexibility and stability needed for modern Cloud Native development.
