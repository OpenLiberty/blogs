= Building custom MCP Servers with Jakarta Servlet on Open Liberty
Morgan Chang <https://github.com/shin19991207>
:imagesdir: /
:url-prefix:
:url-about: /
:example-location: https://github.com/OpenLiberty/sample-langchain4j/tree/main/mcp/server
:blog-building-mcp-client: CHANGE_THIS_VALUE_LATER

Large Language Models (LLMs) are great at reasoning, but they don’t have access to your current or proprietary data. link:https://www.ibm.com/think/topics/model-context-protocol[Model Context Protocol (MCP)] fills that gap by standardizing how AI applications interact with server-hosted capabilities. Think of MCP as REST for AI tools—you expose capabilities via a server, and any MCP-compatible client can invoke them.

MCP defines three types of capabilities:

* **Tools** - Executable functions that allow models to perform actions or retrieve information
* **Resources** - Structured data or content that provides additional context to the model during execution
* **Prompts** - Pre-defined templates or instructions that guide how the model interacts or responds

This post focuses on tools. Instead of using a pre-built link:https://github.com/modelcontextprotocol/servers[MCP server], it demonstrates how to build a custom MCP server on Open Liberty, using Jakarta Servlet and the link:https://github.com/modelcontextprotocol/java-sdk[MCP Java SDK]. If you already have a server and want to connect a Java client, check out the companion post: link:{blog-building-mcp-client}[Building an MCP client on Open Liberty with LangChain4j].

== How does the application work?

This sample demonstrates a Jakarta Servlet application that integrates the MCP Java SDK using its Streamable HTTP transport. It handles protocol messages over HTTP, streams results asynchronously to clients, and exposes MCP tool capabilities.

The application consists of three components:

* **<<tool-implementation, Tool implementation>>** (link:{example-location}/src/main/java/io/openliberty/sample/server/StackOverflowService.java[StackOverflowService.java]) – The business logic behind what your server can do.

* **<<tool-definition, Tool definition>>** (link:{example-location}/src/main/java/io/openliberty/sample/server/StackOverflowAsyncTools.java[StackOverflowAsyncTools.java]) – Prepares methods as MCP tools, including metadata, input schema, and execution logic.

* **<<server-integration, Server integration>>** (link:{example-location}/src/main/java/io/openliberty/sample/server/McpServerInitializer.java[McpServerInitializer.java]) – Registers the tools with the server and exposes them to clients over the transport layer.

When the server is running, all client communication goes through a single `/mcp` endpoint. The interaction pattern follows this flow:

1. The client sends an initialize request via POST to start the session.
2. The client calls one of the registered tools by sending another POST request.
3. The server executes the tool and responds either with a single JSON reply or a streamed Server-Sent Events (SSE) response.
4. To receive live updates, the client opens a GET stream to `/mcp`.

The following sections explain how each part works in detail.

[#tool-implementation]
=== Tool implementation

The link:{example-location}/src/main/java/io/openliberty/sample/server/StackOverflowService.java[StackOverflowService] class defines the main logic behind the MCP tools. Its objective is to fetch relevant questions and answers from Stack Overflow and format them into structured data that the LLM can easily process.

This service defines four tools, each of which queries the public link:https://api.stackexchange.com/[Stack Exchange API] for recent questions and answers:

* link:{example-location}/src/main/java/io/openliberty/sample/server/StackOverflowService.java#L99-L102[searchJakartaEEQuestions()] — Finds recent questions tagged `jakarta-ee`.

* link:{example-location}/src/main/java/io/openliberty/sample/server/StackOverflowService.java#L104-L107[searchMicroProfileQuestions()] — Finds recent questions tagged `microprofile`.

* link:{example-location}/src/main/java/io/openliberty/sample/server/StackOverflowService.java#L109-L112[searchLangChain4jQuestions()] — Finds recent questions tagged `langchain4j`.

* link:{example-location}/src/main/java/io/openliberty/sample/server/StackOverflowService.java#L114-L118[searchStackOverflow(...)] — Performs a free-text search for any query.

The implementation uses the Jakarta EE HTTP Client API to call the Stack Exchange endpoints:

[source, java, role="no_copy"]
----
    private List<Map<String,Object>> questionAndAnswer(String url) {
        List<Map<String,Object>> out = new ArrayList<>();
        ...
            for (Map<String, Object> data : clientSearch(url)) {
                ...
                Map<String,Object> item = new LinkedHashMap<>();
                item.put("Title", title);
                item.put("URL", "https://stackoverflow.com/questions/" + qId);
                item.put("Problem description", stripHtml(body));
                ...
                    List<Map<String, Object>> answers = clientSearch(String.format(FIND_ANSWER_FMT, qId));
                    String topAnswer = answers.isEmpty() ? "No answers." : String.valueOf(answers.get(0).get("body"));
                    item.put("Top answer", stripHtml(topAnswer));
                    out.add(item);
                ...
            }
        ...
        return out;
    }
----

The method returns results in a structured format that is easy for the LLM to parse, contains all necessary metadata (question’s title, URL, problem description, and top answer), and maintains consistency across responses.

[#tool-definition]
=== Defining the MCP tools

The link:{example-location}/src/main/java/io/openliberty/sample/server/StackOverflowAsyncTools.java[StackOverflowAsyncTools] class defines four MCP tool specifications using the `McpServerFeatures.AsyncToolSpecification` API. These specifications follow the MCP protocol for link:https://modelcontextprotocol.io/specification/2025-06-18/server/tools[tools] and wrap business logic methods from the `StackOverflowService` class so the MCP server can expose these operations as protocol-compliant tools.

Each specification includes:

* **Tool metadata** – Name, title, and description.
* **Input schema** – A `JsonSchema` object describing required parameters.
* **Execution logic** – An asynchronous handler for non-blocking, scalable request processing.

==== Tools with parameters

Tools that accept input parameters define a `JsonSchema` object specifying property names, types, and required fields. For example, the free-text Stack Overflow `search()` tool requires a single `query` parameter of type `string`:

[source, java, role="no_copy"]
----
    public AsyncToolSpecification search() {
        JsonSchema inputJsonSchema =
            new JsonSchema(
                "object",
                Map.of(
                    "query", Map.of("type", "string")
                ),
                List.of("query"),
                null,
                null,
                null
            );
        ...
----

The `inputJsonSchema` is passed into the tool definition via the https://modelcontextprotocol.io/specification/2025-06-18/schema#tool[Tool] builder. The tool is then wrapped in an `AsyncToolSpecification` with a handler that extracts the `query` parameter and passes it to the link:{example-location}/src/main/java/io/openliberty/sample/server/StackOverflowService.java#L114-L118[StackOverflowService.searchStackOverflow(...)] method:

[source, java, role="no_copy"]
----
        ...
        Tool tool = Tool.builder()
            .name(...)
            .title(...)
            .description(...)
            .inputSchema(inputJsonSchema)
            .build();

        return AsyncToolSpecification.builder()
            .tool(tool)
            .callHandler((McpAsyncServerExchange exchange, CallToolRequest request) ->
                Mono.fromCallable(() -> {
                    String query = (String) request.arguments().get("query");
                    ...
                    List<Map<String,Object>> output = stackOverflowService.searchStackOverflow(query);
                    ...
                        resultBuilder.structuredContent(Map.of("results", output));
                    ...
                    return resultBuilder.build();
                }).onErrorResume(error ->
                    ...
                )
            )
            .build();
    }
----

link:https://projectreactor.io[Project Reactor] provides the link:https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Mono.html[Mono] type to represent a single asynchronous result. In MCP tool handlers, logic is wrapped using link:https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Mono.html#fromCallable-java.util.concurrent.Callable-[Mono.fromCallable()] to execute non-blocking operations. Errors are handled with link:https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Mono.html#onErrorResume-java.lang.Class-java.util.function.Function-[Mono.onErrorResume()], allowing graceful fallback responses.

==== Tools without parameters

Tools that don’t require input use an empty input schema. The `noArgsTool()` helper, which is used by the `jakartaEETop()`, `microProfileTop()`, and `langChain4jTop()` tools to retrieve top questions, constructs a `JsonSchema` object with no properties:

[source, java, role="no_copy"]
----
    private AsyncToolSpecification noArgsTool(...) {
        JsonSchema emptyJsonSchema = new JsonSchema(
            "object", Collections.emptyMap(), null, null, null, null);
        ...
    }
----

[#server-integration]
=== Integrating the MCP Streamable HTTP transport with Jakarta Servlet

To integrate MCP with Jakarta Servlet, the application registers the SDK's link:https://modelcontextprotocol.io/specification/2025-06-18/basic/transports#streamable-http[Streamable HTTP transport] as a servlet and initializes the MCP server during application startup. The transport serves link:https://www.jsonrpc.org/[JSON-RPC] on a single `/mcp` path.

The link:{example-location}/src/main/java/io/openliberty/sample/server/McpServerInitializer.java[McpServerInitializer] class implements Jakarta Servlet's link:https://jakarta.ee/specifications/platform/10/apidocs/jakarta/servlet/servletcontextlistener[ServletContextListener] interface to manage the server lifecycle:

[source, java, role="no_copy"]
----
public class McpServerInitializer implements ServletContextListener {
    ...
}
----

The class overrides two methods:

* `contextInitialized()` — Creates and registers the HTTP transport, builds the MCP server, and registers the defined tools:

+
[source, java, role="no_copy"]
----
    @Override
    public void contextInitialized(ServletContextEvent sce) {
        ServletContext ctx = sce.getServletContext();

        transport = HttpServletStreamableServerTransportProvider.builder()
            .jsonMapper(McpJsonMapper.getDefault())
            .mcpEndpoint("/mcp")
            .build();

        Dynamic registration = ctx.addServlet("mcp-streamable", transport);
        registration.addMapping("/mcp");
        registration.setAsyncSupported(true);
        registration.setLoadOnStartup(1);

        server = McpServer.async(transport)
            .serverInfo("mcp-stackoverflow-server", "1.0.0")
            .capabilities(ServerCapabilities.builder()
                .tools(true)
                .logging()
                .build())
            .tools(
                stackOverflowAsyncTools.jakartaEETop(),
                stackOverflowAsyncTools.microProfileTop(),
                stackOverflowAsyncTools.langChain4jTop(),
                stackOverflowAsyncTools.search()
            )
            .build();
    }
----

+
At application startup, the initializer creates an instance of `HttpServletStreamableServerTransportProvider` with the default JSON mapper and maps it to the `/mcp` endpoint. It then enables asynchronous I/O and marks the servlet to load on startup.
+
The MCP server is built on top of the same transport by calling `McpServer.async()`. The builder configures basic information such as server name and version, enables capabilities for tools and logging, and registers the tool definitions from the `StackOverflowAsyncTools` class using the `.tools()` method.
    
* `contextDestroyed()` — Gracefully shuts down the server and closes the transport when the application stops.

Because Liberty automatically scans for annotations, the SDK’s `HttpServletStreamableServerTransportProvider` class, which carries a link:https://github.com/modelcontextprotocol/java-sdk/blob/main/mcp-core/src/main/java/io/modelcontextprotocol/server/transport/HttpServletStreamableServerTransportProvider.java#L60[@WebServlet] annotation without explicit URL patterns, can trigger an link:https://www.ibm.com/docs/en/was-liberty/core?topic=messages-srve[SRVE9989E] error about incomplete servlet metadata.

To prevent this, the link:{example-location}/src/main/webapp/WEB-INF/web.xml[web.xml] sets the application `metadata-complete` as `true` to turn off scanning and declares only the bootstrap listener:

[source, xml, role="no_copy"]
----
...
<web-app ... metadata-complete="true">
  <listener>
    <listener-class>io.openliberty.sample.server.McpServerInitializer</listener-class>
  </listener>
</web-app>
----

The `/mcp` mapping itself remains programmatic, as defined in the `McpServerInitializer` class.

== Conclusion: Building MCP servers with Jakarta EE on Open Liberty

In this tutorial, we've demonstrated how to implement a custom MCP server using Jakarta Servlet on Open Liberty. For simplicity, the sample application focuses on the MCP tool capability and wraps the public Stack Overflow API, allowing you to focus on protocol and server wiring.

To extend this example for your own use cases, consider implementing additional MCP capabilities:

* Creating tools that interact with internal APIs, databases, or business logic
* Defining prompts that guide LLMs through complex tasks or workflows
* Registering resources that expose internal documentation, metrics, or domain-specific knowledge

By combining MCP with Jakarta EE’s enterprise-grade features, you can build scalable, intelligent systems that respond to real-time data, automate operations, and deliver meaningful insights to users.
